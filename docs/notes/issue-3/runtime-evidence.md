# Runtime and transfer evidence

Copyright © 2026 Christopher Snow.

Executed 23 October 2026 on this Linux cloud workspace, using the production Vite build and real single-thread core. These are observations on a development VM, not phone performance promises.

The baseline manifest contains 182 files, about 9.6 MB uncompressed. Processing adds 32,367,068 bytes of pinned core binaries and notices, separately opted into for offline use. The optional Big Buck Bunny excerpt is 86,088 bytes. Neither `encoder/` nor `optional/` appears in the baseline manifest. Home and Capture request neither core binaries nor the optional excerpt. Actual transfer depends on HTTP compression and existing browser caches.

A fresh-context local production run measured wall time from clicking Create video-only MP4 to its real probe result: Chromium 913 ms, Firefox 1,307 ms. Clicking Add synthetic sound to the MP4 through its real two-stream probe took Chromium 344 ms, Firefox 921 ms. Both produced a three-second, 960 × 540 H.264/AAC file of 59,698 bytes for this exact original fixture and settings. This includes local tool loading and UI/probe completion, not an isolated encoder microbenchmark; unrelated regression tests were also running. Network transfer time on public hosting is additional and connection-dependent.

No reliable peak process/worker/WASM memory measurement was available from these browser runs. JavaScript heap snapshots would omit substantial WASM and media allocations, so no peak-memory figure is claimed. Inputs, output size, resolution and duration are bounded; every processing operation terminates its worker on completion/error/cancel. Physical-device memory and performance remain unverified.

Real desktop capture was exercised on virtual X11, separately from the canvas-surface integration test; see [native capture](native-capture.md) for output measurements and limitations. The browser suites exercise all production processing operations from the displayed controls, download the newly generated bytes, and compare them with native ffprobe. The independent checker additionally re-executes the downloaded editing recipe with native FFmpeg.
