## Fact brief for separate drafting

- Container, streams, codec, pixel/frame/dimensions, metadata and brands: `inside-video/inspect`. MP4 packages video/audio; H.264/AAC specify encoded stream representations. A codec is not the containing file format. Demuxers read streams from containers; muxers package streams (`export/format`). Neither implies decoding/encoding or writing separate files. isom means the ISO Base Media File Format family, not uniquely MP4; mp41 declares MP4 version 1 compatibility. Brands declare compatibility, not verified conformance.
- Bitrate is data per second of playback, not speed. At a fixed duration higher average whole-file bitrate means a larger file. Quality also depends on source/codec/settings (`quality/quality`). Distinguish bits from bytes without adding invented measured figures.
- Video frame is one picture; frame rate counts pictures per second (`frames-time/rate`). Source fixtures have 854×480 pixels and regular 24 fps. Audio sample rate is measurements per second per channel: supplied audio is 48000 Hz; this is a different count from video fps (`inside-video/inspect`). Audio channel is a separate signal, e.g. left/right stereo; sample value amplitude is multiplied by volume=0.5 in `sound/level`, not a promise of half perceived loudness.
- Timestamp marks when media belongs on a timeline; presentation timestamp specifies display/play time. Time base is seconds per stored timestamp tick; video source has 1/12288 (`frames-time/timestamps`). Do not equate a tick with one frame or average fps with regular spacing for arbitrary media.
- Duration is a length of playback, distinct from a source end time (`first-edit/shorten`, `first-edit/start`). A keyframe offers a decoding starting point; copied cuts can begin earlier than requested due to dependencies (`cut-join/keyframes`). Stream copy transfers encoded streams without decoding/re-encoding; picture/audio filters require decoded media (`cut-join/copy`).
- Encoding represents pictures/audio samples using a codec; decoding reconstructs pictures/audio samples from that representation. Encoding is not universally compression and re-encoding cannot recover detail already lost. Lossy compression saves data by representing detail less precisely (`quality/quality`, `cut-join/copy`). CRF is libx264's quality-oriented control, lower values generally preserve more detail/use more bits, not fixed bitrate/file size; current lesson compares 18 and 35. Preset controls encoding effort rather than playback speed, and equal CRF across presets does not guarantee identical quality (`quality/speed`).
- Scaling changes picture dimensions (`framing/scale`), cropping keeps a rectangular region (`framing/crop`), padding adds canvas around a picture (`framing/pad`). A pixel is one picture-grid location; dimensions/resolution 854×480 means width854, height480, not perceived quality. Pixel format describes how decoded picture component samples are stored; yuv420p is a concrete example (`export/format`). Do not confuse pixel format with a codec/container.
- A filter processes pictures or audio samples (`framing/scale`, `sound/level`); a subtitle is timed text, with SRT cues as the supplied example. Burned-in subtitles become picture pixels (`text/subtitles`). Metadata describes media, e.g. duration and brand fields, and is distinct from the pictures/sound (`export/verify`).
