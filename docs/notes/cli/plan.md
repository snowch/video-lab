# Command-first production labs

Copyright © 2026 Christopher Snow.

23 October 2026. The owner explicitly requires CLI labs rather than GUI editing controls. This supersedes the previous production-lab forms. Retain navigation, accessible command entry, real media replay, file/permission dialogs and offline installation controls. The five production steps teach commands as their primary interaction; fixture-based reference lessons remain explanatory references with existing bookmarks/progress.

Prerequisites: browser/files and ordinary terminal familiarity; introduce media flags beside runnable examples. Real FFmpeg/ffprobe WASM executes learner arguments, not preset identifiers. Browser capture is a named workspace command bridging getDisplayMedia/MediaRecorder, explicitly distinguished from native FFmpeg capture. No OS shell is emulated: no pipes, redirection or expansion. Quoted argument parsing and errors precede prose. Workspace files live in browser IndexedDB with session fallback, limits and explicit downloads; preserve/migrate existing project media without deleting old storage. Files, logs and commands survive changing lesson steps; navigation cancels active work and releases capture tracks.

Commands: help, ls, scene, capture [--audio], stop, sample, fixtures, import, reference build|edit, comparison, ffmpeg ARGUMENTS, ffprobe ARGUMENTS, play FILE, download FILE, rm FILE, clear, cancel. Workspace bounds: twelve media files plus twelve recipes, twenty-four total, 32 MiB combined and 20 MiB per file. Real output logs, exit status, preview/download and a source-hashed execution recipe establish provenance. FFprobe JSON uses the pinned core's documented -1 sentinel only with valid nonempty JSON and no error object. Other probe output formats are outside this initial browser adapter. Native FFmpeg commands remain portable; workspace built-ins are labelled browser conveniences.

The initial path: capture/import/provided source → encode supplied pictures and mux sound with typed commands → ffprobe source → edit a trim and then a two-range concat command → replay/download MP4 and exact recipe. Explain ordering, stream mapping, missing audio, half-open ranges and reset clocks. Examples must be executed against actual original fixtures before a separate prose agent drafts instructions. Never pass a GUI slider value into a supposedly editable command. Existing saved reference challenges and platform remain unchanged.

Checks: parser/argument planning unit tests; real browser WASM commands with modified arguments and measured outputs/native ffprobe; bad syntax/unknown flags/missing inputs/nonzero failure; cancellation/retry; permission denial/actual MediaRecorder capture/cleanup; own input; no silent source substitution; files/history persistence; offline no-tools failure plus saved-tools run; phone/desktop both themes, keyboard, overflow; existing reference/installation/update checks. Separate draft → reader → sceptic → ranked fixes → independent checker, full npm run check, CI/Pages and live verification. Record precise limitations and preserve pre-existing audit files.
