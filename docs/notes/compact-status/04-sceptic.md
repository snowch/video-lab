## Retained findings

1. **R1 retained, Medium: panel height assumes a fixed header height and exceeds the viewport when badges wrap.** Independently reproduced the reader's main-entry findings at 390 × 844 with default text: an offline/failed-check badge wraps the summary and puts the panel at y=160.86 with height 700, bottom=860.86. The optional entry is also affected, bottom=846.88. At 200% root text size the main entry is more affected: 390 × 844 gives y=379.31 and bottom=935.31; 1440 × 900 gives bottom=966.02. These are real panel-boundary failures, rather than evidence that download/restart actions disappear: the panel and document can scroll, but the inner scroll region extends below the current viewport and needs additional page scrolling. `max-height: calc(100dvh - 9rem)` does not follow the actual header height. Size the disclosure against its actual visible position and verify wrapped/error badges and enlarged text, including short screens. Evidence: `layout.json`, `states.json`, the corresponding screenshots and `main-1440-200.png`.

2. **R3 retained, Medium: enlarged desktop optional panel clips its left edge.** Independently reproduced the reader's 1440 × 900, 200% text case: the optional panel is x=-12, width=1280. It uses a viewport-based width but a right offset relative to a narrower centred header. Document `scrollWidth` does not flag this left overflow. Constrain the panel to its actual containing block or explicitly clamp both viewport edges. Evidence: `optional-1440-200.png` and `desktop200.mjs` output.

3. **R2 retained, Medium: enlarged main desktop summary becomes a tall central column.** Independently reproduced the reader's 1440 × 900, 200% case: the closed summary is 169.89 × 299.22. This affects the central compactness goal and is not a demand that enlarged text retain a single row. The header's unshrinking side columns leave too little space for the middle disclosure. Allow the header to reflow when text enlargement makes the side columns consume the available width. The main entry at 320 × 568 and 200% also develops horizontal overflow (summary right=320.31, viewport=320). Evidence: `main-1440-200.png`, `layout.json`.

4. **R4 retained with scope qualification, Medium: optional disclosure does not consistently follow enlarged root text.** Independently measured root text at 200%: main title/body/buttons are 32px, badges 25.6px; optional title/buttons remain 16px, paragraph text 14px, while badges become 25.6px. The fixed `body { font-size: 16px }` is pre-existing, so this is not a new global optional-entry regression. The new shared component nevertheless mixes root-scaled badges with fixed inherited title/body text and cannot provide a consistent enlarged-text reading experience. A local scalable component base is a suitable scope; wholesale optional-entry typography changes are not necessary to resolve the component finding. Recheck bounds after correction. Evidence: independent `font.mjs` computed-style probe and reader `results.json`.

## Tested concerns rejected

- **Update and offline states were not collapsed into one claim.** A normal online page shows “Up to date” with “Not saved offline”. Going offline shows “Cannot check for updates” while preserving the separate unsaved badge. Aborted release metadata shows “Couldn’t check for updates”, with Retry and the full reason inside. Source review confirms `latest` is still produced by the unchanged release-check hook, not inferred from a worker or cache.
- **The short preparation-error label does not hide the cause.** A deliberately mismatched deployed metadata build leaves a closed “Update unavailable” badge and the complete existing explanation/recovery text inside Version. Going offline afterwards does not erase that operation result. This is an intentional failed-preparation probe, not evidence of a prepared update or a second real release. Both entries behaved alike (`focus.json`).
- **Escape from the nested removal confirmation does not close its parent disclosure.** Both entries leave the panel open and restore focus to Remove offline copy. A second Escape closes the panel and focuses its summary. The explicit Close App status button also returns summary focus (`focus.json`).
- **Unsupported offline APIs do not claim saved availability or expose unavailable actions.** Removing the caches API before app initialisation produces “Offline unavailable”, the exact supported-browser explanation, and no download/removal buttons, while online version checking remains independent (`states.json`). This is simulated API absence, not a claim of testing a second browser engine.
- **No identity substitution or safety-engine change was found.** Embedded commit/build identity and its source link remain inside Version; the diff changes no engine/hook/worker protocol. The preparation, restart, progress/cancel and scoped removal actions retain their prior handlers and guards. Existing hook/worker suites remain necessary; this visual review does not certify every cache/restart state.
- **Ordinary layouts fit.** Both entries at 1365 × 768, 390 × 844, 768 × 400 and 390 × 400 with default successful-check text have panel bounds inside the viewport and no horizontal overflow. Native disclosure keyboard activation, normal summary touch height and focus behaviour were observed.

## Review limits

The normal/error/unsupported probes ran in headless Chromium. Layout probes used dark mode; the reader owns the broader light/dark matrix. Root `font-size: 200%` checks enlarged text rather than browser zoom. No new claims are made about actual complete-offline downloads, multiwindow activation or Firefox here; those remain covered by the builder's required suites and the independent checker. No new third-party assets were used, and the pre-existing learner-audit records were preserved.

The builder should resolve the four presentation findings, then have a checker inspect the rebuilt page. This review alone is not a green deployment decision.
