# Ranked fixes — App status

The independent reader and sceptic retained three findings; the sceptic additionally proved the old single-reply protocol incompatibility.

1. **R1, empty storage-limited restart:** restart guards now distinguish empty unavailable media storage from non-durable in-memory files and unsaved drafts. Course and standalone empty workspaces can update, while real in-memory imported work, processing, saves, composition and unsaved notes still veto restart. Per-window session drafts prevent one tab from replacing another's command; the old shared draft remains the new-window fallback.
2. **R2, removal/re-download lifecycle:** scoped removal keeps the lightweight controlling registration while deleting this app's download caches. An immediately re-registered still-controlled worker could return an activated but disappearing registration; keeping it avoids that demonstrated lifetime trap. Registration is never evidence of offline availability. Removal has its own visible busy state, disables conflicting actions, and fences earlier asynchronous readiness replies. User databases/localStorage/sessionStorage and sibling caches/registrations remain untouched.
3. **R3, preparation is not activation permission:** a prepared manifest and an explicitly authorised restart are separate persisted records. Natural worker activation after every tab closes keeps the previous active asset snapshot; reopening still shows the old running identity and pending badge. Only the safe all-window restart selects the new snapshot. A naturally activated worker can later complete that explicit restart without requiring a second worker installation. Failure/cancellation preserves the old snapshot and verified completeness.
4. **S4, old download protocols:** legacy string DOWNLOAD and DOWNLOAD_ENCODER send only their final reply. Verified progress uses the new structured requests. The retained old message names remain usable by older clients and partial saves.

Further author browser testing caught Firefox-specific timing: Cancel can precede worker registration/selection, and controllerchange can precede the worker's activated state. Early cancellation is retained before starting any asset transfer; the UI shows Stopping download until acknowledgement/cleanup. Restart participation also observes the committed worker's statechange, without treating a controller change alone as permission to reload.

The running summary shows commit plus deterministic build suffix, so two builds from one source commit remain distinguishable. Source links live inside the Version section, keeping the disclosure's hit area unambiguous. Exact offline totals come from deployed build metadata or the active snapshot's embedded manifests, including after a partial disconnected launch. No large download begins just to check a release.

Initial author failures are retained in scratch logs rather than counted as passes. Some were test assumptions (notes are in Reference controls, standalone editor/cancel labels differ, Retry resets to Update after reload); others revealed the real disclosure-link, removal, early-cancel and Firefox state ordering issues above. The independent records explicitly distinguish their pre-fix review from the checker that follows.

The final checker found **C1**, a bounded recovery gap after natural worker activation: dropping active-worker ACTIVATE left Restarting for the generic three-minute transfer timeout. Active activation now has the same short recovery class as status/control requests; the real two-build regression drops that request, expects failure without changing A, then retries to B. Waiting-worker activation retains its existing bounded acknowledgement/controller check.

The author also added an incoherent-deployment fault: valid metadata describes C while the actual worker/assets are B. Preparation now passes the expected build and manifest version, which the worker rejects before downloading or writing a prepared marker if they differ. Retrying after coherent B metadata stages the actual B asset set. The all-window restart also rechecks the cohort immediately before recording intent, aborting if an additional app window joined while acknowledgements were gathered.

The checker retained **C2**, an interrupted full-save repair after a deferred worker naturally activates. Full download/resume now targets the selected active snapshot, while update preparation targets the worker's own release. Both structured operations validate the requested build and manifest before saving a marker. Repairing A cannot mark B prepared or promote it when the network describes C. Explicit full-download intent survives partial failure or eviction, so a subsequent update preserves the requested tools. App status cache operations also participate in the restart guard, preventing another window from restarting during an active save/removal.
