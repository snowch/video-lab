## Retained directions

1. **Export format: modest option-note improvement.** Quote: `-pix_fmt yuv420p` → “Store the output pictures as yuv420p.” The immediately preceding concept already explains planar 8-bit 4:2:0 accurately, so do not repeat that explanation wholesale. Change the option's absolute “Store” to “Request” and add the same direct pixel-formats reference used by the three image lessons. A short reminder of 8-bit 4:2:0 is reasonable if it makes the linked option useful in isolation. Check actual output in the log, as the page already requests. Evidence: [FFmpeg n5.1.4 ffmpeg.texi lines 968–976](https://github.com/FFmpeg/FFmpeg/blob/n5.1.4/doc/ffmpeg.texi#L968-L976) explicitly documents a warning and encoder-supported fallback. Existing verified component facts and appendix are in `01-facts.md`; no new sampling claim needed.

2. **Padding: low-priority coordinate clarification.** Quote: “then the picture’s horizontal and vertical position, separated by colons.” The calculation and variable names are already explained. The one small missing literal detail is that these positions are pixel offsets from the output canvas's top-left corner (x first, y second). Add that within the existing option note if extending it; no separate coordinate lesson needed. This makes the formula's results interpretable as placement, rather than arbitrary fractions of spare space. Evidence: [FFmpeg n5.1.4 pad documentation](https://github.com/FFmpeg/FFmpeg/blob/n5.1.4/doc/filters.texi), `pad` section, `x`/`y` specifies offsets relative to the top/left border; its `pad=640:480:0:40` example explicitly identifies column 0, row 40. Source copy in `/workspace/scratch/option-audit-b/filters.texi`.

3. **CRF: optional, low-priority numeric clarification.** Quote: “Set the CRF target to 18 with -crf.” The concept already teaches direction and variable bitrate, so the only useful addition is that 18 is a value on libx264's quality-factor scale, not 18% quality. Avoid adding a universal numerical range: other encoders and bit depths have different controls/ranges, and FFmpeg's wrapper itself exposes a float rather than a percentage. Evidence: [n5.1.4 encoders.texi, libx264 CRF](https://github.com/FFmpeg/FFmpeg/blob/n5.1.4/doc/encoders.texi#L2553-L2554); [libx264.c](https://github.com/FFmpeg/FFmpeg/blob/n5.1.4/libavcodec/libx264.c#L696-L698) passes the literal numeric value directly to `f_rf_constant`; its AVOption at line 1110 defines `crf` as `AV_OPT_TYPE_FLOAT`. This is a small preventative clarification, not a finding that existing prose is wrong.

## Rejected expansion candidates

- **Scale `-2`: already fully explained.** Scale's option says it calculates a proportional height rounded to a multiple of two and explicitly says it is not negative height. Its explanation also distinguishes stored-grid proportions from display proportions through SAR. Pad/reuse explain the same special value locally. Pinned [scale documentation](https://github.com/FFmpeg/FFmpeg/blob/n5.1.4/doc/filters.texi) confirms the `-n` rule and output SAR adjustment. No extra general negative-number tutorial.
- **Amplitude/decibels:** the level page explicitly says each sample is multiplied by one half, defines amplitude and distinguishes it from perceived loudness. Practice applies one quarter to the original source. No dB value is used in these commands; introducing dB is new subject matter rather than explaining an unexplained literal. Pinned `volume` documentation gives `output_volume = volume * input_volume`.
- **Fade:** `t=out`, `st=5`, `d=3` have individual notes naming fade-out, start in seconds and duration in seconds; explanation computes second 5 to second 8. No missing units. Pinned `afade` documentation confirms aliases `type,t`, `start_time,st` and `duration,d`.
- **Preset `fast`/`ultrafast`:** concept explicitly distinguishes encoding effort from playback speed; worked explanation interprets log `speed=2x`; practice explains the extra effort of `fast` relative to `ultrafast`. No missing option semantics.
- **Null/dash:** decode's option notes already explain `-f null` discarding processed media, required output destination `-`, absence of downloadable media and absence of command piping. Explaining native stdout plumbing adds no necessary notebook meaning here.
- **Text:** title options explain filter, quoted argument, colon-separated names, font path, literal text, pixel font size and colour; explanation supplies default position/time. Subtitle options explain cue file, font directory versus font selection, internal family name and unavailable device fonts. No retained gap.
- **Faststart, structured probe and workflows:** notes already explain flag `+`, copy versus second pass, JSON selection, stream/file report scope and units, shell versus notebook, native batch options and shell punctuation. No retained gap.
- **Optional mapping suffix `?`:** none of these 15 pages' actual commands uses an optional map selector. No addition warranted here; any occurrence elsewhere belongs to its own page audit.
