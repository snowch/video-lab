## Ranked material findings

No material learner-blocking or decision-making finding retained. The built changes address the reported assumed-knowledge gap. No fixes requested by this reader.

1. **Primary complaint addressed.** The codec guide starts with “For an ordinary video with sound, start with MP4 containing H.264 video and AAC audio”, followed by the actual export-lesson link. “The receiving app or device is where your video will be watched, edited or uploaded” defines the previously abstract choice. The visible numbered procedure supplies Download, open/import/upload, recognisable picture, audible expected sound and intended start/end checks. “Playback inside this course tests this browser only” explains why that extra test matters. This is a working first action and observable success criterion, without prerequisite codec research. Evidence: [desktop codec page](/workspace/scratch/actionable-guidance/reader/desktop-light-appendix-codecs.png), [phone codec page](/workspace/scratch/actionable-guidance/reader/phone-light-appendix-codecs.png).
2. **Alternatives have a sensible optional scope.** “Investigate it if an editor or service requests HEVC, or if you need to compare compression options for a large video” supplies a reason to leave the default. The HEVC/VP9/AV1 and audio entries do not have to teach a native encoder workflow to fulfil this optional reference's purpose. The default remains available before these choices, and the receiving-file test has already been taught. Format rows similarly give material/purpose choices: “Start with JPEG for photographs and PNG for sharp text, diagrams or transparency”; container and pixel-format pages link directly to the taught test. The capability section clearly separates storing, processing and previewing formats. Evidence: [formats](/workspace/scratch/actionable-guidance/reader/desktop-light-appendix-formats.png), [containers](/workspace/scratch/actionable-guidance/reader/desktop-dark-appendix-formats-video-containers.png), [pixel formats](/workspace/scratch/actionable-guidance/reader/phone-dark-appendix-formats-pixel-formats.png).
3. **Export instruction stands on its own.** “Before delivering a video, download a short export and open it on the phone or player that will show it, import it into the receiving editor, or upload it to the website that will receive it” supplies the action locally; the following sentence supplies picture/sound/timing checks and limits the conclusion to the tested file/setup. A learner need not discover the appendix to understand what to do. The existing detailed encoder, container and sampling explanation remains coherent. Evidence: [export page](/workspace/scratch/actionable-guidance/reader/desktop-light-export.png).
4. **Personal images are an optional extension after a complete worked example.** The supplied-file lessons introduce timing and give a concrete replay observation before “Use your own pictures (optional)” or “Use your own drawings (optional)”. The disclosures teach one canvas, consistent PNG export mode/transparency, consecutive filenames, import and actual `ffprobe` comparisons. “If they differ, return to the editor and export again” provides recovery; the pattern and new output filename make continuation concrete. The animation uses a distinct `sketch-` prefix. The 25 fps image report is explicitly separated from sequence timing. This is sufficient preparation without turning the main exercise into an image-editor lesson. Evidence: [open sequence extension on phone](/workspace/scratch/actionable-guidance/reader/phone-dark-learn-image-video-sequence-open.png), [open animation extension](/workspace/scratch/actionable-guidance/reader/desktop-light-animation-details.png).
5. **Recording uses the present app path.** “Return to the course overview, open Files and choose Import files” matches the actual route and controls, including the 20 MiB limit and exact input-filename substitution. The mobile version additionally explains exporting from Photos into device Files when necessary. I followed both back links and imported a local copy of the course's practice MP4 as `reader-recording.mp4`, selected its filename and obtained the replay. This validates the import instruction, not native screen recording on an operating system. Evidence: [mobile recording instructions](/workspace/scratch/actionable-guidance/reader/phone-dark-appendix-recording-Phone.png), [desktop return/import control](/workspace/scratch/actionable-guidance/reader/recording-return-import-files.png), [phone imported-file replay](/workspace/scratch/actionable-guidance/reader/phone-recording-imported-replay.png).

## Rejected expansions and limits

I did not retain a demand for a codec compatibility database, commands for every optional codec, new controls for choosing publication services, or an image-editor tutorial. Those additions would broaden this reference and repeat information beyond the identified gap. The short local export procedure and more detailed shared reference serve different entry points; the repeated minimum actions are useful rather than competing instructions. I found no material duplication or obligatory research chore in the added guidance.

This is an independent focused built-page reader review, not the full quality gate. I did not run `npm run check`, execute the lesson encodes or native OS capture commands, certify every external service's requirements, or audit unchanged pages outside this assignment. The author/source notes were consulted after forming the initial built-page judgement. No production changes or commits were made.

Raw screenshots, metric records and standalone review scripts are outside the repository at `/workspace/scratch/actionable-guidance/reader/`. `matrix.json`, `enlargement.json`, `interactions.json` and `extra-ui.json` record the actual observations. Scripts were run from `/workspace/video-lab` with `node`; their evidence paths were updated after relocation. An initial matrix harness attempt used an incorrect locator for the existing radio group, was corrected to the actual labelled radio input and rerun; it was a reviewer-script error, not a product failure.
