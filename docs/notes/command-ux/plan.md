# Test an authentic command experience

Copyright © 2026 Christopher Snow.

The owner rejected invented commands such as `sample` as a confusing learning surface, asked about a mobile/tablet command builder, and then requested an HTML mockup to test the UX. This slice delivers an isolated, interactive prototype before implementing another production redesign. The standing permission to publish reviewed work to main applies to its own optional prototype URL. Existing course routes, engine, platform and learner storage are unchanged.

Hypothesis: ordinary app controls for source selection, import, playback and download; only authentic FFmpeg/ffprobe syntax in a command editor. A touch-friendly optional builder exposes native flags and the complete command. Type mode supports a custom command without silent replacement. Keep one current task, command and bounded result together. Source → Inspect → Trim is a deliberately small UX trial, not a completed new curriculum.

The prototype runs local file selection and playback, source download and command-copy/download. It does not execute FFmpeg, generate edited media, grade learning or write to course storage. Persistent and per-result labels disclose simulated execution. Supplied metadata comes from native ffprobe on the committed original; no measured metadata is invented for imports or custom commands. Capture is visibly unconnected in this prototype. Embed the original source so the HTML can be downloaded and opened without a server.

Verified before prose: native `ffprobe -v error -show_streams -show_format -of json public/media/build-queue.mp4` reports a ten-second 960×540 H.264 video stream and mono AAC synthetic tone, file 128737 bytes. Native FFmpeg 7.1.5 command `ffmpeg -i SOURCE -ss 2 -t 6 -map 0:v:0 -map '0:a?' -c:v libx264 -pix_fmt yuv420p -c:a aac demo.mp4` produces a six-second H.264/AAC output (local evidence `/workspace/scratch/command-ux/demo.mp4`). `-ss` follows the input; `-t` is output duration; optional audio mapping tolerates absent sound. Sound removal uses `-an`. Commands are POSIX-quoted; no operating-system shell is provided by the browser UI.

Follow the mandatory separate prose draft → built fresh learner → separate sceptic → ranked fixes → independent checker workflow. Test phone, tablet and desktop, both themes, native syntax/quoting, simulated versus actual behaviours, builder/manual preservation, reset, navigation, keyboard, output overflow, real import/playback/download and opening standalone HTML. Run the repository quality check before publishing. Testers should try the source path, change a trim duration, explain the resulting command, edit it manually, then return to the builder. Review whether any operation still appears to teach invented CLI syntax or requires a long scroll back to instructions.
