## Command structure and placement

- General FFmpeg form: `ffmpeg [global options] [input options] -i input [output options] output`. The notation in brackets is explanatory, not literal command text; repeat an input group for each source. Current browser cells produce one media output; native FFmpeg can support more.
- Example already taught: `ffmpeg -i bunny-short.mp4 -ss 2 -t 4 later.mp4`. Tool: `ffmpeg`; input introducer: `-i`; input argument: `bunny-short.mp4`; output options: `-ss 2 -t 4`; positional output: `later.mp4`. Option values follow their options; the final filename is not an option. Four seconds is kept from second two; `-t 4` is duration, not the source end time.
- Official general rule: options apply to the next specified file; global options are exceptions and belong first. Per-file options reset between files. For a novice-facing general pattern say input options precede their `-i`, output options precede the relevant output path, global options near the tool name. Do not say every option after `-i` is necessarily an output option: `-filter_complex` is global, and another input group may follow.
- Examples with placement consequences: `ffmpeg -ss 2 -i bunny-short.mp4 -t 3 -c copy rough.mp4` versus `ffmpeg -i bunny-short.mp4 -ss 2 -t 3 exact.mp4`. Input `-ss` seeks to an earlier available seek point; default accurate seeking during transcoding decodes/discards the extra segment, but stream copying preserves it. Output `-ss` decodes/discards until the requested timestamp. Do not imply input `-ss` is inherently inaccurate in all uses, or output `-ss` promises arbitrary sub-frame precision. The copied source's boundaries and timestamps can affect actual output duration and opening.
- `ffprobe bunny-short.mp4` has a positional input and no output filename. `ffprobe -show_streams -show_format -of json bunny-short.mp4` adds report options before that input. These tools do not share all options or meanings.
- `.mp4`, `.wav`, `.m4a` output suffixes let FFmpeg select a muxer (container writer); changing an existing file's name does not convert its content. Default encoders come from the selected output format/build when omitted. `-c:v libx264` makes an encoder choice explicit; `-c copy` avoids re-encoding selected streams. Neither option itself selects streams.
- Numbers start at zero: first `-i` is input 0, second is input 1. `:v` and `:a` denote video/audio stream types. In `-c:v`/`-c:a` they are stream specifiers; `[0:v]` and `[0:a]` in the taught filtergraph are input-stream links. `[v]`/`[a]` are arbitrary filtergraph output labels, later selected by `-map`.
- Quotes group a spaced filename or filtergraph as one argument. They are removed by command parsing; they are not part of the filename/filter value. The browser implements argument quoting, not a Unix shell. It does not execute shell loops, variables, pipes, `>`, command substitution or wildcard expansion. `drawing-%02d.png` is expanded by FFmpeg's image2 demuxer, not by a shell. Current files/folders are browser workspace files, not unrestricted native OS paths.

| Name / exact taught graph fragment | Arguments, mechanics and limits | Destination |
| --- | --- | --- |
| `fps=12` (also 6, 24) | `fps` video filter; target output picture rate. Duplicates/drops frames to make constant rate; does not simply make playback run faster/slower. Image-sequence input rate sets content pace; output fps=24 repeats the images for regular output cadence. | `#/learn/frames-time/rate`; `#/learn/image-video/sequence`; `#/learn/image-video/animation` |
| `scale=640:-2` (320, 480, 360) | Positional width:height. Width fixed; negative height `-2` calculates the other dimension from input aspect ratio and makes it divisible by 2. | `scale=trunc(iw/2)*2:trunc(ih/2)*2` | Native capture filter. `iw`/`ih` input width/height; `trunc` rounds toward zero; positive pixel dimensions round down to even values here. | `crop=480:480` (360:360) | Positional output width:height. Default x/y centre the crop. Removes picture edges, does not shrink whole source picture into square. | `#/learn/framing/crop` |

| `overlay` / `overlay=40:0` | Two video inputs: main picture then overlay image. Defaults x=0,y=0; positional x:y coordinates shift overlay to right by 40 and down by 0 pixels in practice. Source PNG alpha controls transparency. Does not mean “40%”. | `#/learn/image-video/overlay` |

| `volume=0.5` (0.25) | Audio sample-amplitude multiplier; not “half as loud” or a device volume control. Above 1 amplifies and can clip; taught examples reduce sample levels. | `#/learn/sound/level` |

## Literal syntax, placeholders, paths and native shell

A separate syntax section/group can make these searchable without claiming they are FFmpeg CLI options. Link each item back to its existing lesson. These facts should be reflected in entry aliases/search terms (`quotes`, `filename`, `pattern`, `percent`, `colon`, `comma`, `brackets`, `variable`, `shell`, `stdout`, `dash`, `placeholder`).

- Filenames/paths: `bunny-short.mp4`, `later.mp4`, `landscape.jpg`, `fonts/DejaVuSans.ttf`, `captions.srt`, `previews/short.mp4` are literal names in taught commands; replace them only with actual corresponding files. Input and output are distinct; `previews/short.mp4` is a folder-qualified output, not a URL or option. Route `#/learn/workflows/reuse`.
- `drawing-%02d.png` and `frame-%02d.png`: image2 numeric pattern, integer with minimum two digits padded with zeros, giving drawing-01.png etc. This is literal FFmpeg pattern syntax, not an instruction to replace the whole value manually, shell wildcard syntax or an option. Route `#/learn/image-video/sequence` or `/animation`.
- `-` at the end of `ffmpeg -xerror -i bunny-short.mp4 -f null -`: output URL/stdout convention used with null; output data is discarded, not written as a playable result. Route `#/learn/export/decode`.
- `SCREEN_INDEX`: genuine placeholder in macOS recording template; replace with actual listed screen index. `:none` selects no audio input. Index 0 may be a camera; never hard-code it as a screen. `desktop` in Windows gdigrab is a literal capture source, not a placeholder. Route `#/appendix/recording`.
- `${DISPLAY}` and `$XDG_SESSION_TYPE`: POSIX shell variable expansion in native Linux terminal. `printf '%s\n' "$XDG_SESSION_TYPE"` is a shell utility call, not FFmpeg. Continue x11grab only after the actual desktop session identifies X11; Wayland uses a compatible device recorder/import fallback. An XWayland DISPLAY is not proof that full Wayland capture is supported. Route `#/appendix/recording`.
- `+0,0` in `"${DISPLAY}+0,0"`: x11grab input URL offset at upper left, distinct from filter comma chaining. `:none` in AVFoundation similarly belongs to device input syntax. Route `#/appendix/recording`.
- POSIX batch script is exact existing `PageDefinition.nativeScript`, deliberately separate from browser execution. `#!/bin/sh` interpreter declaration; `set -eu` enables unset-variable error and the script's failure exit behaviour; `mkdir -p exports` creates output directory if needed. `-e`, `-u`, and mkdir's `-p` are shell/utility options, not media options.
- `for input in ./*.mp4; do ... done`: shell loop and wildcard enumeration. `[ -f "$input" ] || continue` tests regular file and skips non-file/unmatched literal pattern; this `-f` belongs to test, not FFmpeg's format option. `$input` variable is quoted to preserve spaces. `name=${input##*/}` removes longest matching directory prefix; `${name%.*}` removes shortest matching filename-extension suffix. These are shell parameter expansions, not filename pattern support in the notebook. `ffmpeg -n` avoids overwrite; existing output causes refusal, and the script's `set -e` then stops it. Route `#/learn/workflows/batch`.

## Sample-rate support follow-up

- Confirmed `ffmpeg -hide_banner -h encoder=aac` on native 7.1.5 returns a finite supported-sample-rate list; 24000/16000/8000 are in it and 6000 is absent. Thus “the chosen encoder must support the requested rate” is accurate; do not claim any requested `-ar` value works with every encoder. No exact list is needed in learner prose.
- Follow-up native probe `ffmpeg -hide_banner -i public/media/notebook/bunny-short.mp4 -t 0.1 -vn -ar 6000 -c:a aac -f null -` exited 234 and reported “Specified sample rate 6000 is not supported by the aac encoder”. This is an encoder rejection, distinct from valid 6000 Hz PCM WAV. Existing `docs/notes/overwrite-playback/02-investigation.md`, `06-checker.md` and `07-validation.md` independently confirm real generated PCM at 6000 Hz and decoding in desktop Chromium; the reported physical-device silence was not reproduced. The same-name preview failure/recovery test deliberately injects an error and must not be described as a natural 6000 Hz decoder failure.
- Encoding support and playback support are separate: an encoder accepting a rate does not establish that the receiving browser/device can decode and play its resulting container/codec/sample-rate combination. Retain the existing download-and-test-in-receiving-app guidance.
