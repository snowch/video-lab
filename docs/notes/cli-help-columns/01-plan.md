# Command help columns

Copyright © 2026 Christopher Snow.

The owner expects conventional CLI help: each parameter in a left column, its
description alongside in a right column. The previous visual-design pass arranged
whole parameter/description pairs across several columns; this makes scanning
parameters harder and is superseded by this request.

Retain the existing semantic definition list and its command order. Use one row
per parameter, with one third of the available width for syntax and two thirds
for explanations. Keep the full workspace width. At 600 CSS pixels and below,
stack the description beneath its parameter so phone reading remains usable.
Long parameters wrap; the description column remains aligned across rows.

This is a CSS-only correction with no new learner-facing wording, commands or
behaviour. Existing text therefore needs no new drafting pass. Follow the mandatory
independent reader, sceptic and checker workflow on the built site, then run the
full quality gate. Inspect the pictured frame-rate lesson, the introductory cut,
and longer framing/filter explanations at phone, tablet and desktop widths in
both themes and with enlarged text. Preserve existing controls and navigation.
