## Evidence and boundaries

- Real images and measured sizes come directly from `src/notebook/visuals/media.json`,
  generated by the media evidence agent from the licensed supplied Big Buck Bunny
  clip. The media agent records generation commands, native tool versions,
  dimensions, hashes, source time and full-file sizes. These are supplied native
  examples, never a view of the learner's current editor or browser result.
- Framing images show the same source time: source 854 × 480, `scale=640:-2`
  640 × 360, `crop=480:480` 480 × 480, and
  `scale=480:-2,pad=480:480:(ow-iw)/2:(oh-ih)/2` 480 × 480.
  Figures apply one relative display scale: output width/source width controls
  rendered width. A crop must not be stretched to the source's full display width.
  Stored dimensions do not determine a player's physical display size. Scaling
  can adjust sample aspect ratio; the native metadata is the evidence for that.
- Quality examples independently encode the same original source with libx264
  at CRF 18 and 35. The recorded native commands explicitly select one encoder
  thread, medium preset and AAC audio. These document the supplied run rather
  than promising byte equality with the browser's shorter lesson command.
  Matching 256 × 192 crops are taken
  from the same frame time and source area. The displayed byte count is each
  complete encoded MP4 including audio, not the extracted PNG. No size or quality
  relationship is extrapolated to other sources, encoders or learner commands.
- Stream-copy path is an explicitly identified conceptual model: compressed
  input packets are remuxed into a new file without a decode/filter/encode chain.
  Filtering requires decoded pictures or sound samples. Encoding may change
  compressed quality; copying preserves compressed data and dependencies.
- Dependency figure is deliberately synthetic, labelled A–F. A is a clean
  decoding start in this model. Each later picture references its predecessor;
  requested output starts at C. Copying preserves the need for A and B. Decoding
  may use A and B and discard their decoded pictures before encoding C–F into a
  new beginning. This is not the supplied fixture's actual GOP, timestamp layout,
  packet selection or player opening. Real codecs can reorder pictures and use
  forward references. An I-picture alone need not be a clean random-access point.
  The figure does not claim every copied cut starts visibly early or every
  re-encoded seek matches an arbitrary continuous time between available frames.
- Faststart figure models MP4 box order only, not sizes: header → media → index
  becomes header → index → media. The `moov` box contains indexing metadata needed
  to interpret media. Supplied clips already place it before media. Moving it
  earlier can make indexing available early during download; this does not
  guarantee startup speed or demonstrate a network benefit in local replay.

The figure purpose is visible relationships: bypassed encoding stages, retained
picture dependencies, changed image boundaries, actual encoded detail and size,
and index order. Page prose should retain command-specific guidance and remove
paragraphs that merely repeat the diagram.
