# Offline implementation

Copyright © 2026 Christopher Snow.

The app downloads a complete release on request. `npm run build` builds the ordinary Vite site, then enumerates its files and emits a service worker with a content-derived version and SHA-256 integrity for every asset. `offline-manifest.json` is a build inspection artifact; it is not a runtime dependency. The original bundle contains 165 assets, about 9 MB before compression. The generator also hashes the worker and range implementation when deriving the version.

The worker installs only when all assets are present. Fetches have a 30-second per-file timeout and concurrency four. Valid partial downloads remain available for retry, but incomplete releases never activate. A failed update leaves the active release intact. Integrity mismatch is treated as failure even for an HTTP 200 response. A waiting update activates when the user requests reload or when old controlled tabs close. Active pages reload on a replacement controller; local lesson state is managed separately by the unchanged platform. Activation deletes only old Video Lab caches under this deployment path, retaining unrelated caches.

Document requests for `/video-lab/` and `index.html` use the saved document; hash routes work normally. Only known same-origin assets within this deployment are served from saved responses. Unknown URLs, other apps and external links use the network. Native players receive 206 responses for single byte ranges, including open-ended and suffix ranges, and 416 for unsatisfiable ranges. Unsupported multipart or malformed range requests receive the complete response as HTTP permits. This course's short recordings make buffering the saved recording to slice it practical; this is not a large-video streaming architecture.

The UI checks actual saved-asset presence before readiness, on initial mount and when the window regains focus. Missing assets can be downloaded again. It registers a worker only when asked to download; existing installations remain attached on later visits. Status distinguishes readiness, network status, errors and waiting updates. A new release does not forcibly interrupt a controlled page before an activation request. Updates reload all open controlled tabs; already saved answers, notes and theme remain in localStorage. Partial in-memory activity such as playback position is not promised to survive.

The offline tests use independent real HTTP origins with `Cache-Control: no-store`, not route mocks, so Firefox and Chromium exercise actual service-worker install requests. They verify every manifest response against its hash while offline, all twelve recordings through native playback and seeking, challenge grading and persistence, new-tab reopening, HTTP failure, corrupt HTTP-200 data, retry, storage repair, failed and successful updates, multiple tabs, background updates, unrelated-cache isolation and unsupported browsers. Firefox's forced Fetch `cache: no-store` mode bypassed offline worker handling in the automation environment; normal app fetches pass. Test-origin responses prohibit HTTP caching, so normal-mode asset verification still demonstrates service-worker storage.

No installable home-screen manifest or new dependency is necessary for this scope. Safari, physical mobile browsers and screen-reader announcements are not independently verified; desktop Firefox and Chromium plus Chromium phone emulation are covered. Browser storage eviction/private-session expiry remains a platform limitation explained in the UI. An online initial download is required.

## Status follow-up

Before the independent review was complete, a targeted follow-up corrected a stale status when a background update finished after an earlier successful update check. The browser regression performs a no-change check, then triggers a separate update and requires the waiting-update message to replace “up to date”. It passed all five browser projects. Connection events also preserve an in-progress operation message until that operation resolves.

A final status correction requires an uncached, successful fetch of `sw.js` before a manual update check can report success. The browser's worker-update promise can otherwise resolve using its recently checked state while disconnected. The coordination file is deliberately outside the saved manifest, so this probe reaches the network. This changes only the manual update action; offline app requests continue to use saved assets. Failure still verifies and reports retained active-copy readiness.
